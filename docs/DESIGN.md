# Дизайн рабочего места приёмщика

Задача M/S. Основа — требования AGENTS.md/TASK.md и локальный UI UX Pro Max; коммерческие значения с фотографии не переносились.

## Применённые рекомендации

Проверены запросы `B2B SaaS CRM operations admin data dense dashboard`, `B2B Service`, `form validation autosave data table accessible errors`, `server components forms authentication`. Поиск рекомендовал `Data-Dense Dashboard`, профессиональную тёмно-синюю палитру с синим действием, табличные числа, явные подписи полей и обратную связь при сохранении. Для Next.js — Server Components по умолчанию и проверяемые серверные мутации.

Первый отраслевой запрос с `automotive` вернул рекламный motion-driven стиль. Для ежедневного ввода CRM применены рекомендации каталога по операционным B2B интерфейсам и требования ТЗ. Блоки landing page, анимации и внешние Google Fonts для рабочего приложения не нужны.

## Визуальные решения

- Светлая рабочая область `#F8FAFC`, белые поверхности, основной текст `#020617`, вторичный `#475569`, границы `#E2E8F0`.
- Основной цвет `#0F172A`, действие `#0369A1` с белым текстом. Красный используется для ошибок и опасных действий. Цвет состояния всегда дополнен текстом.
- Системный sans-serif с поддержкой кириллицы, без внешнего подключения шрифтов. Числа — `font-variant-numeric: tabular-nums`.
- Сетка отступов 4/8 px, спокойные разделители, компактные таблицы с сохранением читаемости. Один главный призыв к действию на экран.
- Desktop-first: постоянная навигация на широком экране; перенос/адаптация на планшете и телефоне. Широкая таблица прокручивается в собственном контейнере, не раздвигая страницу.
- Иконки SVG одного набора; кнопки с текстом или доступным названием. Видимый keyboard focus, подписи `label`, минимальные зоны нажатия 44 px для основных действий.

## Навигация и сценарий

Основные разделы: обзор, клиенты, автомобили, заказы, документы. Административные разделы доступны по роли. Связанные данные открываются из заказа и карточки автомобиля.

1. Найти существующего клиента по имени/телефону или создать.
2. Выбрать/добавить автомобиль, не вводя клиента повторно.
3. Открыть заказ: жалоба, пробег, мастер.
4. Заполнить осмотр по разделам; явно отображать «Не проверялось», «Осмотрено», «Требует ремонта», «Рекомендовано», «Выполнено» и независимые L/R.
5. Выбрать позиции для заказа без повторного ввода, отдельно показать работу и выбранный вариант запчасти.
6. Показать серверные итоги: работы, запчасти, скидка, оплачено, остаток. Оригинал и аналог — альтернативы.
7. Сформировать сохранённую версию акта или заказ-наряда; открыть PDF, скачать и распечатать. История версий остаётся доступной.

## Сохранение и ошибки

Поля имеют видимые подписи и ограничения. При запросе кнопка показывает выполнение; ошибки привязаны к полям и доступны screen reader. Ошибочное сохранение не очищает введённые значения. Автосохранение черновика сопровождается состояниями «Сохраняется / Сохранено / Ошибка»; конфликт версий требует обновления, не должен молча затирать правки коллеги. Пустой список показывает следующий доступный шаг. Нереализованные действия не изображаются рабочими кнопками.

## Проверка интерфейса

Проверить основной сценарий с клавиатуры, сохранение после перезагрузки, ошибки валидации, ограничение доступа мастера, таблицы с длинными названиями, PDF с кириллицей и продолжением страниц. Проверить ширины 375, 768, 1366 и 1440 px; не обрезать статусы, суммы и подписи. Нормальный текст должен иметь контраст не ниже 4.5:1; `prefers-reduced-motion` отключает необязательную анимацию.
