# Архитектура и первый сценарий

Дата: 17.11.2026. Источник: AGENTS.md, TASK.md и фотография (структура, без рукописных цен).

## Решение (L)
Модульный монолит: Next.js App Router + TypeScript, PostgreSQL + Prisma. UI обращается к JSON API; серверные services проверяют права и бизнес-инварианты. PDF — отдельный серверный модуль @react-pdf/renderer со встроенным DejaVu Sans. Хостинг не выбран. PostgreSQL одинаков для локального сервера/VPS/облака; Compose готовит локальную БД. На первом этапе одна организация.

Альтернативы: отдельный API увеличивает число компонентов без пользы для одного сервиса; SQLite не соответствует выбранному стеку и конкурентным изменениям. Это инженерный выбор исполнителя в рамках ТЗ.

## Данные
User (ADMIN/RECEPTION/MASTER) → Session; Customer → Vehicle → WorkOrder → InspectionItem / OrderLine → Document. VehicleOwnership сохраняет владельцев. WorkOrder фиксирует клиента на дату открытия; Document содержит JSON-снимок реквизитов, строк, итогов и PDF bytes, версию шаблона. CatalogItem — редактируемый справочник осмотра; ServiceSettings — реквизиты/часовой пояс; AuditEvent — критические изменения. Sequence выдаёт уникальные номера транзакционно. История не удаляется каскадно, клиенты и автомобили архивируются.

Деньги — безопасные целые копейки, количество — тысячные единицы (целое); расчёт bigint с округлением до копейки. Оригинал и аналог — альтернативы. Сервер пересчитывает строки и итоги, не принимает итог от браузера. Нельзя оплатить больше итога, уменьшить итог ниже оплаченного, редактировать выданный/отменённый заказ. Смена статуса только по карте переходов; выдача после полной оплаты. Изменения заказа/осмотра используют optimistic lock (version).

## Безопасность
Пароли scrypt, случайные сессии хранятся как SHA-256, httpOnly SameSite=Lax cookie (Secure при HTTPS). Защита изменения данных — проверка Origin на каждом mutation. Права проверяются в API; MASTER видит только назначенные заказы и необходимые данные их клиентов, не меняет роли, цены, оплаты, документы и настройки. Попытки входа ограничены в БД. Секреты и реальные персональные данные не входят в исходники. Seed создаёт только справочники и администратора из env; нет пароля по умолчанию.

## Навигация
Обзор → Заказы → карточка заказа (осмотр / работы / документы); Клиенты; Автомобили → история; Справочник и Сотрудники для администратора; Настройки. В первом сценарии создание клиента, автомобиля и заказа последовательное. Осмотр сохраняется с явным статусом сохранения/автосохранением и конфликтами версий; перевод отмеченных позиций в строки заказа идемпотентный.

## Проверка готовности
Настоящая PostgreSQL: клиент → автомобиль → заказ с мастером → L/R, рекомендации → две работы и запчасть → два PDF → закрытие → история → повторное открытие исходного PDF. Проверить права MASTER, конфликт версий, арифметику, кириллицу/переносы PDF, перезапуск и backup/restore. Данные тестов синтетические.
