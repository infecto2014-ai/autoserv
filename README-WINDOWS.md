# CRM на Windows: работа на своём ПК

Приложение работает на этом компьютере по адресу **http://localhost:3000**. PostgreSQL хранит данные в локальном Docker volume; сервер Next.js работает в открытом окне терминала. Публикация в интернет и облачная база для этого запуска не нужны.

## Что установить один раз

1. Windows 10/11 с поддержкой WSL 2 и включённой виртуализацией.
2. **Node.js 24 LTS** либо Node.js **22.12+ из ветки 22**, вместе с npm: https://nodejs.org/. Node.js 20, 23 и 25 для этого проекта не подходят. После установки заново откройте терминал/Проводник, если `node` ещё не найден.
3. **Docker Desktop**: https://www.docker.com/products/docker-desktop/. При необходимости установите WSL 2 по подсказкам установщика и перезагрузите ПК. В Docker Desktop должен быть выбран режим **Linux containers**, движок должен показывать готовность.
4. Скачайте исходники проекта, распакуйте архив в постоянную папку, например `C:\CRM\sto-crm`. Файлы `Setup-Windows.cmd`, `Start-Windows.cmd`, `compose.yaml` и `package-lock.json` должны находиться в этой папке. Пути с пробелами поддерживаются. Не запускайте файлы прямо внутри ZIP.

Python, отдельная установка PostgreSQL и Poppler для работы CRM не нужны. Docker Desktop должен оставаться установленным и иметь достаточно места для зависимостей, образа PostgreSQL и растущей базы.

## Первый запуск — с интернетом

1. Запустите Docker Desktop и дождитесь готовности движка.
2. Дважды щёлкните **`Setup-Windows.cmd`**. Окно остаётся открытым для сообщений и ошибок.
3. Если `.env` ещё нет, мастер запросит email, имя администратора и **собственный пароль из 12–256 символов** с повтором. Пароль вводится без отображения символов. Готового стандартного пароля нет. Используйте уникальный пароль и сохраните его в менеджере паролей.
4. Дождитесь сообщения «Подготовка завершена». Setup устанавливает закреплённые npm-зависимости, загружает Docker-образ PostgreSQL, запускает БД, применяет миграции, создаёт первого администратора и каталог осмотра, собирает production-версию приложения. Клиенты и заказы автоматически не создаются.
5. Дважды щёлкните **`Start-Windows.cmd`**. После подтверждения готовности откроется браузер. Войдите с email и паролем, выбранными в мастере.

Setup только подготавливает приложение; сервер запускает отдельный Start. Первоначальная подготовка может занять несколько минут. Интернет нужен для установки Node.js/Docker Desktop, `npm ci` и загрузки Docker-образа. После успешной подготовки обычный запуск работает без интернета.

Мастер создаёт `.env` в UTF-8: случайный пароль PostgreSQL, локальную базу `sto_crm`, пользователя `sto`, `APP_ORIGIN=http://localhost:3000`, `TIMEZONE=Europe/Kaliningrad`, отключённую телеметрию Next.js и выбранные данные администратора. Пароль БД отдельно запоминать не нужно. Файл содержит секреты — сохраните его вместе с резервной копией в защищённом месте, не отправляйте в git или переписку. Для совместимого формата `.env` значения должны быть однострочными; редкое сочетание обоих видов кавычек и `#` в одном значении мастер может попросить заменить.

**Если `.env` уже существует, Setup сохраняет его и проверяет обязательные поля.** Он не перезаписывает пароли и не очищает базу. Повторный seed сохраняет пароль существующего администратора, настройки и изменённые позиции каталога. При ошибке настройки исправьте указанные поля в своём `.env`, затем повторите Setup. Не копируйте незаполненный `.env.example` поверх рабочего файла.

## Следующие запуски — без интернета

1. Запустите Docker Desktop, дождитесь готовности.
2. Дважды щёлкните **`Start-Windows.cmd`**.
3. Оставьте открытым окно сервера и работайте в браузере на http://localhost:3000.

Start использует локальные `node_modules`, production-сборку `.next` и уже загруженный образ PostgreSQL. Он не вызывает `npm ci`, `npx`, загрузку образов или сборку; БД запускается с `docker compose up -d --pull never --no-build --wait db`, затем применяются локальные миграции. Движок Prisma обязан уже находиться на диске. При неполной установке Start сообщает о необходимости Setup.

Браузер открывается только после успешного ответа `/api/health` с идентификатором `sto-crm` и статусом `ok`. При повторном запуске Start узнаёт уже работающую CRM и открывает её. Если порт занят другим приложением, запуск прерывается и браузер не открывается.

Сервер слушает только `127.0.0.1`, PostgreSQL — только `127.0.0.1:5432`. Этот режим предназначен для работы на одном ПК. Интернет не нужен для оформления заказов, истории и генерации PDF; шрифты находятся в проекте.

## Как остановить

В окне сервера нажмите **Ctrl+C**, затем закройте окно после сообщения об остановке. В Windows терминал может дополнительно спросить о завершении пакетного файла. Закрытие вкладки браузера само по себе сервер не останавливает.

PostgreSQL остаётся запущенной в Docker; данные сохраняются. При необходимости остановите её в Docker Desktop или выполните в PowerShell из папки проекта:

```powershell
docker compose stop db
```

Обычная остановка, перезагрузка ПК и повторный Start сохраняют базу. **Не используйте `docker compose down -v`, удаление volume `sto-crm_postgres-data` или сброс данных Docker Desktop: это удалит клиентскую базу.** Не меняйте PostgreSQL-пароль в `.env` после создания базы без отдельной процедуры смены пароля в самой БД.

## Сохранение данных

Папка проекта содержит код, `.next`, зависимости и `.env`. Клиенты, заказы, документы и пользователи находятся в Docker volume `sto-crm_postgres-data`. Копия только папки проекта не является резервной копией базы; перемещение исходников на другой ПК не переносит volume.

Для стандартной установки (`POSTGRES_USER=sto`, `POSTGRES_DB=sto_crm`) можно сделать дамп в PowerShell из папки проекта, пока Docker Desktop и БД работают:

```powershell
New-Item -ItemType Directory -Force backups | Out-Null
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
docker compose exec -T db pg_dump -U sto -d sto_crm -Fc -f /tmp/sto-crm-backup.dump
if ($LASTEXITCODE -ne 0) { throw 'Ошибка резервного копирования' }
docker compose exec -T db pg_restore --list /tmp/sto-crm-backup.dump
if ($LASTEXITCODE -ne 0) { throw 'Ошибка проверки архива' }
docker compose cp db:/tmp/sto-crm-backup.dump ".\backups\sto-crm-$stamp.dump"
if ($LASTEXITCODE -ne 0) { throw 'Ошибка копирования архива' }
```

Храните дампы и копию `.env` отдельно от ПК и вне git, с ограничением доступа. Проверка списка архива не заменяет пробное восстановление. Восстанавливайте проверенную копию сначала в отдельной установке; восстановление поверх рабочей базы заменяет данные. Дополнительные скрипты резервного копирования/восстановления для Bash описаны в [README.md](README.md#резервное-копирование-и-восстановление).

## Ошибки и изменение настроек

- **Node.js не найден / неподдерживаемая версия:** установите Node.js 24 LTS или 22.12+ из ветки 22 и откройте окно заново.
- **Docker недоступен:** запустите Docker Desktop, дождитесь готовности; проверьте WSL 2 и режим Linux containers. В PowerShell должны успешно выполняться `docker info` и `docker compose version`.
- **Нет образа PostgreSQL / зависимостей / `.next/BUILD_ID` / движка Prisma:** подключите интернет и повторите Setup. После обновления исходников также выполните Setup перед Start; не переносите `node_modules` между Windows и Linux.
- **Порт 5432 занят:** остановите другую локальную PostgreSQL или другую установку CRM. Локальный launcher рассчитан на порт БД 5432 и не подключается к внешнему серверу.
- **Порт 3000 занят другим сервисом:** остановите его или задайте в `.env` `APP_ORIGIN=http://localhost:3001`, затем повторите Start и используйте этот адрес. Допускаются только HTTP `localhost` и `127.0.0.1` без пути. Сервер всегда привязан к `127.0.0.1`.
- **Ошибка пароля БД:** `DATABASE_URL` должен соответствовать `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`; специальные символы пароля в URI должны быть percent-encoded. Изменение `.env` не меняет пароль уже созданного volume. Не удаляйте volume для исправления ошибки.
- **Не получается войти:** используйте email и пароль первоначального администратора. Повторный Setup и изменение `ADMIN_PASSWORD` в `.env` не сбрасывают пароль существующего пользователя.
- **Ошибка миграции/сборки:** сохраните текст ошибки без `.env` и паролей, исправьте причину и повторите Setup. Не удаляйте данные для повторной установки.
- **Браузер не открылся:** после сообщения «CRM готова» откройте показанный локальный адрес вручную. Если готовность не подтверждена, проверьте сообщения сервера.

Для запуска из PowerShell или другого терминала, в том числе проверки без открытия браузера:

```powershell
node scripts/local.mjs --help
node scripts/local.mjs setup
node scripts/local.mjs start --no-open
```

Логика launcher проверяется автоматическими тестами на Linux; выполнение `.cmd`, интерактивного мастера и Docker Desktop непосредственно на Windows в текущей среде не проверялось.
