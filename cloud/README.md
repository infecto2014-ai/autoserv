# Сервис CRM: временная облачная версия

Полноценный серверный вариант CRM для Sites/Cloudflare Workers с постоянной D1 (SQLite) базой. Исходный Next.js/PostgreSQL проект и Windows-запуск остаются в https://github.com/infecto2014-ai/autoserv. Эта версия не использует браузерное localStorage для клиентских записей.

## Возможности

Клиенты → автомобили → заказ с мастером →110 пунктов осмотра/L/R/рекомендации → работы/выбранные запчасти → сохранённые PDF акта и заказ-наряда; история автомобиля, сотрудники/роли, каталог, настройки, CSV. Снимки документов и сами PDF хранятся в D1; повторный просмотр не генерирует документ заново.

Деньги в целых копейках, дробные количества в тысячных; D1.batch с CHECK guard защищает версию заказа и все дочерние изменения от частичной записи. Нет удаления истории каскадом. Цены, статусы, оплаты и документы отражаются в аудите.

## Доступ

Сайт создаётся закрытым для владельца. Вход и выход обслуживает Sites через ChatGPT; отдельные пароли CRM не создаются. Первый допущенный владелец получает ADMIN, остальные сотрудники сопоставляются с разрешённым email/постоянным providerId. Для доступа сотрудника необходимы разрешение на сам Site и профиль в CRM; создание профиля само по себе не расширяет audience Site.

## Разработка и проверка

Node24 (тесты используют node:sqlite), npm ci, npm run typecheck, npm test, npm run build. Для PDF-тестов нужен Poppler (pdfinfo/pdftotext/pdffonts). Build создаёт один Worker ES module dist/server/index.js со встроенными UI-ресурсами и шрифтами; нет загрузок внешних шрифтов или Node/WASM на сервере.

Файлы миграций находятся в drizzle/ и применяются платформой при публикации. Request handlers не создают/изменяют схему. Каталог и настройки заполняются отдельно после авторизованного входа, существующие изменения не перезаписываются.

Развёртывание: .openai/hosting.json содержит постоянный Site ID и логический D1 binding DB; source Git синхронизируется с провайдером Sites до сохранения версии, архив содержит точный Worker build и SQL-миграции. Временный экземпляр использует отдельную базу; локальные данные пользователя автоматически не загружаются.
